# Multi-GLB composition update

The model picker and Scene → Add files accept one or several GLBs. Additional GLBs append to the current project; other model formats and project ZIPs remain single-file imports. Each selected file receives its own scene root. Equal names are suffixed, and equal source bytes may share immutable asset storage without sharing editable object identities.

Every default-scene GLB node becomes an editable group with its original local transform. Nodes with geometry have a child instance selecting that node's own primitives. This preserves nesting without drawing a child's mesh twice. Meshes, points, materials, textures and immutable original metadata stay with the original asset; the layout document stores placement and visibility separately. Skins, morphs, GPU-instanced nodes, invalid graphs and sheared matrices fail explicitly.

The tree supports selection, expand/collapse, local visibility and whole-subtree hiding. Hiding a parent preserves children's individual visibility preferences. Independent file roots prevent cross-file node-ID collisions. Batch addition is one Rust-owned command and one Undo step; replayed command IDs do not add duplicates. Node selectors are checked against mesh nodes in the immutable GLB's default scene before committing.

GLBAdapter origins are restored as `[east, elevation, -north]` metres. A declared CRS mismatch is rejected. Missing CRS or vertical datum remains unregistered, and no datum conversion is inferred. Very large coordinates still require explicit registration/rebasing before scene layout; the local preview limit remains 100 km. Original assets remain usable through the source workflow.

The advanced controls now share dark inputs, compact spacing, focus indicators and panel typography. Five bundled domain presets have explanations and small example workflows: General geometry, Indoor/rooms, Product assembly, Geospatial and Subsurface. Presets change classes and tool visibility only, never source geometry or coordinate units.

Verification includes original synthetic multi-mesh fixtures, duplicate filenames, independent file roots, source-node fidelity, parent transforms, subtree visibility, batch rollback/Undo/Redo and reopen. The supplied well A/B, terrain/horizons and straightened BHA examples load through the real GLTFLoader in CPU tests. This is not a WebGL visual or Windows launch qualification.

Verification checkpoint: 154 root Rust tests and six JavaScript suites passed. The real-router integration test also exported the two-file scene to ZIP and restored it into a separate store with equal IDs, node selectors and root visibility. Five changed critical source files were downloaded from private Drive and byte-compared. The later ZIP assertion was uploaded and size-verified. No new live WebGL or Windows launch qualification is claimed; the browser remains reserved for the user's sign-in.

Packaging follow-up: the earlier GNU crossbuild used a separate WebView2Loader.dll because the pinned binding statically links the loader only for MSVC. Two one-job MSVC attempts were killed by SIGKILL while compiling windows 0.61.3, including a retry at opt-level 0 / 256 codegen units for that binding only. No source or linker diagnostic identified an application defect, but no single-EXE output was produced. Build capacity remains a blocker; source and compiled cache are preserved. The older GNU binary does not contain this multi-GLB update and is not the requested final deliverable. A static loader would still require the Microsoft WebView2 runtime; it does not embed the whole browser. Existing CDN JavaScript dependencies also mean this candidate is not offline-qualified.
